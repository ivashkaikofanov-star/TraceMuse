# Правовой контекст РФ и локальные снимки

По умолчанию TraceMuse показывает отдельные ссылки на официальные реестры и указывает необходимость ручной сверки. Приложение может искать точные упоминания по локальному снимку, если у вас есть выгрузка официального источника. Для каждого совпадения отчёт содержит запись, категорию, адрес источника, дату выгрузки и дату аудита.

1. Откройте «Настройки» → «Официальные реестры». Список идентификаторов и полных официальных URL доступен также в `/api/settings` в поле `legal_registries`.
2. Соберите снимок из выгрузок, указывая дату получения, точные названия и номера записей. Сохраняйте исходные официальные выгрузки для сверки.
3. Поместите файл в `backend/data/registry_snapshot.json`. В локальный `backend/.env` добавьте `LEGAL_SNAPSHOT_PATH=data/registry_snapshot.json` и перезапустите TraceMuse.

Структура одного блока показана ниже. Угловые скобки обозначают поля, которые заполняют по официальной выгрузке.

```json
{
  "version": 1,
  "registries": {
    "foreign_agents": {
      "source_url": "https://minjust.gov.ru/ru/pages/reestr-inostryannykh-agentov/",
      "retrieved_at": "<YYYY-MM-DD>",
      "entries": [
        {"value": "<точное название из выгрузки>", "reference": "<номер записи>"}
      ]
    }
  }
}
```

Коды остальных разделов: `undesirable_organizations`, `extremist_materials`, `extremist_organizations`, `terrorism_extremism`, `restricted_sites`. Для `restricted_sites` в `value` используют точный ASCII-домен без схемы и пути. Остальные категории проверяются по извлечённому тексту и текстовым метаданным. Сопоставление ограничено набором записей конкретного снимка.

Локальная копия может устареть и не содержать все записи. Для совпадений сверяйте действующий статус, контекст использования и возможные требования к маркировке на дату публикации. Для категорий без локального снимка приложение показывает ручной режим.
